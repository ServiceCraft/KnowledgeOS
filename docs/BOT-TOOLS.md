# Bot Tools (Б4)

Инструменты, которые LLM может вызывать в цикле генерации ответа. Это не REST API — они описаны для разработчиков и интеграторов, чтобы понимать, как бот добывает данные и как это связано с источниками и guardrails.

Реализация: [backend/internal/chat/tools](backend/internal/chat/tools). Аргументы валидируются по JSON-schema **до** исполнения; вызывать можно только зарегистрированные (whitelist) инструменты; цикл ограничен `maxToolIterations = 5`.

## Общие правила (guardrails вокруг tool-calls)

- **Whitelist** — диспетчер исполняет только инструменты из реестра ([registry.go](backend/internal/chat/tools/registry.go)).
- **Валидация аргументов** по JSON-schema перед исполнением ([validate.go](backend/internal/chat/tools/validate.go)); некорректные аргументы возвращаются модели как tool-result с ошибкой, а не исполняются.
- **Лимит итераций** — на последней итерации инструменты отключаются, чтобы гарантировать текстовый ответ и завершение.
- **Источники**: инструменты возвращают `Result.Sources`, которые попадают в `chat_messages.sources` и участвуют в постпроверке цитирования (Б5).

## search_knowledge

Поиск по базе знаний (статьи, QA, услуги) через гибридный ретривер Б2.

| параметр | тип     | обяз. | описание                                  |
|----------|---------|-------|-------------------------------------------|
| `query`  | string  | да    | Запрос на естественном языке (minLength 1)|
| `top_k`  | integer | нет   | 1..10, сколько фрагментов вернуть          |

Возвращает `results[]` (`source_id`, `title`, `content`, `score`) и источники для grounding.

## get_pricing

Чтение прайса тенанта с лимитом. Контракт ограничен, чтобы не отдавать всё дерево без ограничения.

| параметр | тип     | обяз. | описание                          |
|----------|---------|-------|-----------------------------------|
| `query`  | string  | нет   | Фильтр по названию услуги/узла     |
| `limit`  | integer | нет   | Максимум возвращаемых позиций      |

## get_service_info

Получение описания конкретной сущности базы знаний по типу и идентификатору. Для поиска по названию сначала используйте `search_knowledge`.

| параметр      | тип    | обяз. | описание                               |
|---------------|--------|-------|----------------------------------------|
| `source_type` | string | да    | `article` / `qa` / `pricing`           |
| `source_id`   | uuid   | да    | UUID исходной сущности                  |

## request_handoff

Запрос передачи диалога живому оператору. Tool не отправляет сообщение во внешний канал напрямую; он возвращает машинный сигнал, который `ChatService` превращает в `guardrail_action=escalate`, после чего handoff-модуль переводит сессию в `waiting_operator`.

| параметр | тип    | обяз. | описание                                  |
|----------|--------|-------|-------------------------------------------|
| `reason` | string | нет   | Короткая машинная причина эскалации        |

Используется, когда клиент явно просит оператора или модель понимает, что безопасный ответ по базе знаний невозможен.

## Связь с Б5

Результаты инструментов — это **данные**, а не инструкции. Финальный ответ, опирающийся на tool-результаты, проходит ту же постпроверку цитирования и скоринг уверенности, что и ответ на RAG-prefetch. Выдуманные источники бракуются независимо от того, пришли они из prefetch или из инструмента.
