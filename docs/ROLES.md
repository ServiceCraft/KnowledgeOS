# KnowledgeOS — Пользователи и роли

## Ролевая модель

| Роль (UI)            | ID (API)     | Права                                                                 |
|----------------------|--------------|----------------------------------------------------------------------|
| Оператор             | `viewer`     | Только чтение: списки, карточки, комментарии (без записи), поиск.     |
| Менеджер             | `editor`     | Чтение + редактирование бизнес-сущностей (статьи, темы, прайс, Q&A, комментарии). |
| Администратор        | `admin`      | Всё, что Менеджер, **плюс** раздел «Пользователи». Без системных настроек. |
| Супер администратор  | `superadmin` | Полный доступ: пользователи, импорт/экспорт БД, backup, системные настройки. |

ID ролей стабильны и используются в API; локализованные имена — только для UI.

### Матрица прав

| Действие                                   | viewer | editor | admin | superadmin |
|--------------------------------------------|:------:|:------:|:-----:|:----------:|
| Просмотр базы знаний и поиск               |   ✅   |   ✅   |  ✅   |     ✅     |
| Редактирование бизнес-сущностей            |   —    |   ✅   |  ✅   |     ✅     |
| Раздел «Пользователи»                       |   —    |   —    |  ✅   |     ✅     |
| Назначение роли «Супер администратор»       |   —    |   —    |  —    |     ✅     |
| Импорт/экспорт базы данных                  |   —    |   —    |  —    |     ✅     |
| Backup-сервис и системные настройки         |   —    |   —    |  —    |     ✅     |

Любая операция записи под ролью `viewer` отклоняется backend с `HTTP 403`.

## Раздел «Пользователи»

Доступен в меню «Настройки → Пользователи» (для ролей Администратор и Супер
администратор; для остальных пункт скрыт).

Возможности:

- список с пагинацией, поиском по e-mail, фильтром по роли и сортировкой по дате;
- создание учётной записи (e-mail, начальный пароль ≥ 8 символов, роль, статус);
- редактирование (e-mail, роль, статус активности);
- сброс пароля (ввод вручную или генерация);
- деактивация / удаление учётной записи.

### Ограничения безопасности (enforced на backend)

- Доступ к разделу и эндпоинтам `/api/v1/admin/users` — только `admin`/`superadmin`.
- Назначить/снять роль «Супер администратор» может только Супер администратор.
- Учётными записями Администраторов и Супер администраторов управляет только
  Супер администратор: Администратор **не может редактировать или удалять других
  Администраторов** (и Супер администраторов), но может редактировать
  собственную учётную запись.
- Нельзя изменить собственную роль, деактивировать или удалить свою учётную запись.
- Пароли хранятся как bcrypt-хеш и никогда не возвращаются в API.
- Минимальная длина пароля — 8 символов (валидация на клиенте и сервере).
- Деактивированный пользователь не может авторизоваться, а его refresh-токены
  отзываются при деактивации, смене роли и сбросе пароля (вход и обновление
  токена сразу блокируются). Уже выданный access-токен перестаёт действовать в
  пределах своего срока жизни (≤ 15 минут).
- Все операции выполняются в рамках компании текущего администратора (multi-tenant).

### API

```
GET    /api/v1/admin/users          # список (фильтры: q, role, sort, page, limit)
POST   /api/v1/admin/users          # создание
PATCH  /api/v1/admin/users/{id}     # обновление (email, role, is_active, password)
DELETE /api/v1/admin/users/{id}     # удаление
```

Все эндпоинты требуют JWT и серверной проверки роли вызывающего.
