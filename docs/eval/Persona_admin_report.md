# Агент-администратор: доводка тона и записи на приём (B-1)

> Дата: 2026-07-13. Цель: агент общается как администратор ветклиники — отвечает по
> актуальным QA/FAQ и записывает на приём. Харнесс: `tone_eval.py` (10 сценарных
> диалогов + автопроверки), `run_eval.py` (контракт «ответ-или-handoff»),
> `yclients_mock.py` (mock YCLIENTS API для e2e-проверки записи).

## Что изменено (код)

1. **Системный промпт переписан** (`service/chat.go: buildSystemPrompt`):
   персона администратора с правилами стиля (на «вы», 1–4 предложения, приветствие
   только в первом сообщении, один уточняющий вопрос, предложение следующего шага);
   слаг тона (`friendly_professional`) теперь переводится в понятную модели
   формулировку; пошаговый сценарий записи через yclients_* (подтверждение деталей
   до создания записи, без числовых id в тексте); упоминание инструментов только
   когда соответствующий модуль включён; **текущая дата (Europe/Moscow)** — без неё
   модель подставляла прошедший год в дату записи.
2. **Критический баг tool calling** (`llm/yandex/openai.go`): по OpenAI-спеке
   `function.arguments` приходит JSON-строкой; адаптер передавал её как есть, и
   валидатор отклонял каждый вызов («arguments must be an object») — инструменты
   (включая запись YClients) не работали вовсе. Добавлены unquote при приёме и
   quote при отправке истории.
3. **Чистка служебной разметки** (`chat/guardrails`): футер «Источники: [...]»
   вырезается во всех вариантах (отдельной строкой, приклеенный к прозе, пустой
   `[]`, не-source_id ссылки вида `[price.zoomedic.ru]`); повторное приветствие в
   середине диалога срезается детерминированно (`StripRepeatedGreeting`).
4. **Настройки компании** (данные, повторить на stage/prod): `model_tier: pro` —
   YandexGPT **Lite не выполняет function calling** (пишет псевдовызовы текстом),
   для записи через YClients нужен pro; `persona_rules` — правила ветклиники
   (бережность, кличка питомца, «не ставь диагнозов, предложи приём», острые
   состояния → срочно в клинику); модуль `yclients_booking: true`.

## Проверка

**Сценарные диалоги (`tone_eval.py`) — 10/10 PASS** (транскрипты:
`tone_eval_report.json`): цена, здоровье питомца (без диагноза, предложение
записи), полная запись на приём (4 хода), запрос оператора → эскалация,
вне-доменный вопрос, грубый клиент, prompt-injection → отказ, экстренный случай,
отсутствие повторного приветствия. Автопроверки: нет утечек источников/промпта/
имен инструментов/id, нет повторных приветствий.

**Запись e2e через mock YCLIENTS**: услуга → специалист → слоты → имя/телефон →
подтверждение → `book_record` создан с верными service_id/staff_id/датой
(«завтра» → 2026-07-14T10:00, год корректен).

**Регрессия контракта (`run_eval.py`, pro-модель)**:
- 118 QA с заполненным ответом: **114 PASS_ANSWER**, 3 уточняющих вопроса по
  «записьным» QA (корректное поведение администратора), 1 HANDOFF.
- 60 случайных QA без ответа: 52 ответа синтезом / 8 HANDOFF, **0** нарушений
  «ответ-или-handoff».
