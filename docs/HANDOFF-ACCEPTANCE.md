# Handoff Acceptance Smoke

Цель: проверить, что клиентский диалог гарантированно переходит к оператору, оператор отвечает, а бот молчит до возврата диалога.

## Подготовка

1. Войти как `superadmin`, открыть `/admin/companies` и выбрать тестовую компанию.
2. Войти как `admin` этой компании и открыть `/settings/bot`.
3. Включить бота, `enabled_modules.handoff`, нужный канал Telegram/MAX/VK и `escalate_on_low_confidence`.
4. Для Telegram сохранить token metadata с `webhook_secret` и `handoff_notification_chat_id`.
5. Создать минимум одного пользователя `viewer` — это оператор.

## Smoke 1: Обычный Ответ Бота

1. Отправить в Telegram вопрос, который покрыт базой знаний.
2. Ожидаемый результат: клиент получает ответ бота, сессия остается в состоянии `bot`, в `/bot/handoff` она не появляется.

## Smoke 2: Явная Просьба Оператора

1. Отправить клиентом: `позовите оператора`.
2. Ожидаемый результат: клиент получает fallback-текст передачи специалисту.
3. В `/bot/handoff` во вкладке `Ожидают` появляется сессия `waiting_operator`.
4. В Telegram-группу операторов приходит уведомление, если задан `handoff_notification_chat_id`.

## Smoke 3: Работа Оператора

1. Войти как `viewer`, открыть `/bot/handoff`.
2. Нажать `Взять диалог`.
3. Ожидаемый результат: сессия переходит в `operator`, composer становится активным только для назначенного оператора.
4. Отправить ответ оператора.
5. Ожидаемый результат: клиент получает сообщение во внешнем канале, transcript показывает роль `Оператор`.

## Smoke 4: Бот Молчит В Handoff

1. Пока сессия в `operator`, отправить новое сообщение клиентом.
2. Ожидаемый результат: webhook отвечает `ok`, сообщение клиента появляется в transcript, бот не отправляет автоответ.

## Smoke 5: Возврат И Закрытие

1. Нажать `Вернуть боту`.
2. Отправить новый вопрос клиентом.
3. Ожидаемый результат: бот снова отвечает, сессия в состоянии `bot`.
4. Повторить handoff и нажать `Закрыть`.
5. Ожидаемый результат: сессия `closed`, операторский composer недоступен.
6. Открыть `/bot/playground`, выбрать закрытую сессию и попытаться отправить сообщение.
7. Ожидаемый результат: composer недоступен, виден баннер «Диалог закрыт»; для продолжения нужна «Новая сессия».

## Smoke 6: Права

1. Войти вторым `viewer`.
2. Открыть чужой назначенный диалог.
3. Ожидаемый результат: отправка/закрытие/возврат недоступны в UI или возвращают `403` на backend.
4. Войти как `admin`.
5. Ожидаемый результат: admin может управлять активными handoff-диалогами tenant.

## Smoke 7: Выключенный Handoff

1. Выключить `enabled_modules.handoff`.
2. Спровоцировать низкую уверенность или явную просьбу оператора.
3. Ожидаемый результат: система не обещает передачу оператору и не ставит сессию в `waiting_operator`.
